# 元素校准

三条链路的页面元素都写在配置里，不写在代码里。

| 链路 | 配置 |
| --- | --- |
| 眼镜 | config/app_glass.yaml |
| 戒指 | config/app_ring.yaml |
| 手表 | config/app_watch.yaml |

三条链路已接入真实包名：眼镜 `com.moyoung.glasses`、戒指 `com.moyoung.ring`、手表 `com.crrepa.band.dafit`。若 yaml 里仍是 `com.example.*` 占位，实机任务不能启动。

## 校准步骤

1. 手机连上电脑，打开对应 APP 并停在升级页。
2. 执行 `python -m uiautomator2 screenshot` 不可作为定位依据。定位用界面 dump：

```bat
python -c "import uiautomator2 as u2; print(u2.connect().dump_hierarchy())" > runtime\uia_dump\page.xml
```

3. 在 dump 里找到下面这些控件，只改 yaml 的 `value`，不要改键名。

| 键 | 用途 |
| --- | --- |
| upgrade_entry | 进入升级页的入口 |
| upgrade_button | 开始升级的按钮 |
| version_field | 实报版本：优先稳定文案（眼镜/戒指「当前版本」，手表「您的固件是最新版本」旁的固件号） |
| announced_field | 目标版本：手表用「有新版本可以更新」旁的固件号；眼镜/戒指可与 version 同文案 |
| githash_field | 固件 githash |
| progress_text | 进度百分比 |
| progress_keywords | 「正在升级」「传输中」一类文案 |

4. 控件没有 resourceId、文本也不稳定时，给 `fallback.upgrade_button` 写屏幕比例坐标，例如 `[0.5, 0.82]`。元素点击失败才会用这个坐标。
5. `device_name` / `device_mac` **不要写死某一台设备**。留空即可：任务开始时会按 App 页面控件（有 resourceId 时）和该包名的 GATT 连接自动识别。`device_keywords` 只用于多个已配对设备时收窄范围。换表/换镜/换戒不用改 yaml。
6. `ui_connected` / `ui_disconnected` 写成 APP 设备卡片上的真实文案。
7. APP 能导出日志时，把 `log_export.support` 设为 true，并写要点击的文本路径和手机上的导出目录。不能导出就设为 false，工具会改抓该进程的 logcat。
8. 改完后先跑 `python -m unittest server.tests.test_core`，再在页面上只勾 T01、轮次 1，用真机试一轮。
