# 穿戴 OTA 产品实现方案

本地工具。USB 只连一台手机，自动点穿戴 App 做固件升级，判定结果，留下日志、截图和报告。

工具不改 PHP 后台。升级包由测试人员事先在后台配好。

## 1. 给谁用

测试人员用它代替手工点升级、记结果。

一次只测一台手机、一条穿戴链路。测完拔线，换下一台，再开新任务。

## 2. 两种入口，同一套逻辑

| 入口 | 怎么开 | 给谁 |
| --- | --- | --- |
| 源码 | `python start.py`，浏览器打开 `http://127.0.0.1:8765/` | 改代码、改配置时用 |
| 便携版 | 双击 `WearableOTA.exe`，弹出桌面窗口 | 发给测试人员 |

窗口和网页操作一样：选 App、勾用例、填次数、开始、看日志、下报告。便携版不另开浏览器。

没有真机时用 `python start.py --dry-run`，走假设备，只验证调度和报告，不调用 adb。

服务只听本机 `127.0.0.1:8765`，不对外网开放。

## 3. 做和不做

做：

- 拉起 App，进升级页，点升级，等到结束
- 升级过程中按用例注入干扰（杀 App、关蓝牙、关 Wi-Fi、切后台、息屏）
- 判定成功、失败、死机、环境异常
- 写出 HTML、CSV、`result.json`，并留运行日志和截图

不做：

- 不改 PHP 后台，不替人配升级包
- 不同时控多台手机
- 不覆盖需要人手的动作：重启穿戴设备、把设备拿远、拔插充电线、升级中途插充电线

## 4. 三条链路

三条链路分开配置、分开执行。页面元素和进度来源不一样，判定规则共用。

| 链路 | App | 配置 | 执行脚本 | 升级路径 | 进度怎么看 |
| --- | --- | --- | --- | --- | --- |
| 手表 | DaFit，`com.crrepa.band.dafit` | `config/app_watch.yaml` | `server/scripts/run_dafit_flow.py` | 设备页 → 固件升级 → 升级 | 页面百分比 |
| 眼镜 | daecho，`com.moyoung.glasses` | `config/app_glass.yaml` | `server/scripts/run_glass_flow.py` | 首页 → 设置 → 固件 → 升级 | 页面百分比，以及 `X-LOG` 里的进度和写入偏移 |
| 戒指 | Da Ring，`com.moyoung.ring` | `config/app_ring.yaml` | `server/scripts/run_ring_flow.py` | 我的 → 固件升级 → 固件升级 | 页面没有百分比，看 logcat `onProgressChanged` |

传输差异：

- 手表、戒指固件只走蓝牙。升级中关 Wi-Fi，这一次仍然必须成功。
- 眼镜固件同时走蓝牙和 Wi-Fi。关 Wi-Fi 会打断这一次，必须重新点升级并成功。
- 眼镜升级页有两块固件：主控、影音。任务里可以只勾一块，也可以两块都勾。默认主控。

设备名和 MAC 不写死在配置里。优先从 App 设备页读取；蓝牙 dumpsys 经常只有 MAC 没有名字，读不到名字时会打开设备页再填。换机不用改 yaml。

## 5. 用例

用例在 `config/cases/`。勾哪几条、每条跑几次，由当次任务决定。按勾选顺序串行，一条跑满次数再跑下一条。

T02 是同版本反复（S1），T03 是 A/B 交替（S2）。两条不能放在同一次任务里。

| 编号 | 名称 | 升级中做什么 | 怎样算过 |
| --- | --- | --- | --- |
| T01 | 基线升级 | 不干扰 | 升级成功，设备页已连接 |
| T02 | 单版本反复 | 不干扰 | 同上。版本号可以不变 |
| T03 | A/B 交替 | 不干扰 | 方向交替，升级成功并重连 |
| T04 | 升级中杀 App | 进度到约 20% 后杀 App 再打开 | 这一次允许被打断；重新点升级必须成功 |
| T05 | 升级中关蓝牙 | 关蓝牙再打开 | 同上 |
| T06 | 升级中关 Wi-Fi | 关 Wi-Fi 再打开 | 手表、戒指这一次必须成功；眼镜允许被打断，重新点升级必须成功 |
| T07 | 升级中切后台 | 回桌面再拉回前台 | 升级必须成功 |
| T08 | 升级中息屏 | 关屏保持约 60 秒（期间盯传输日志），再亮屏复查 | 升级必须成功。失败记问题，不能放过 |
| T09 | 充电中升级 | 要求穿戴设备在充电（App 显示「充电中」等，不是手机 USB） | 升级必须成功 |

触发干扰的条件：页面出现「正在升级 / 传输中」一类文案，或进度达到 20%。到点还没出现，就按兜底延时再注入。注入后会回读系统开关，没真正关掉就不算测到，记跳过。

长稳压测：只勾 T02 或 T03，次数填 200。

## 6. 一次任务怎么走

```
选链路、勾用例、填次数
        │
        ▼
确认只有一台手机，且包名不是占位符
        │
        ▼
按顺序跑每一条、每一轮
  拉起 App → 进升级页 → 点升级
  → 该干扰就干扰 → 等到结束 → 需要重连就确认重连
  → 写一条结果
        │
        ▼
写出报告，释放这台手机
```

调度约定：

- 同一时刻只跑一个任务。有任务在跑时，再点开始会被拒绝。
- 相邻两轮之间默认停 20 秒，给设备准备下一次握手。第一条不等。
- 单条失败后，可恢复的失败最多再跑 1 次（配置 `case_retry_times: 2`，含第一次）。环境异常和死机不重试。
- 这一轮已经开始写固件，失败后不再自动整包重刷，避免把设备刷进 bootloader 开不了机。T04、T05 用例内部的「重新点升级」不受这条限制。
- 单条代码异常记 ERROR，继续下一条。连续 2 条异常才停整场任务。
- 环境异常（没包、没登录、电量过低、手机掉线、蓝牙关着）立刻停整场，后面的轮次记跳过。
- 设备死机后，同任务剩下的场景记跳过。
- S2 且后台同一时刻只能生效一条包时，把 `config/global.yaml` 的 `s2_model` 改成 `single`。方向不对时任务暂停，人切完后台再点「继续」。默认 `multi`，可无人值守交替。

页面上改的断开观察窗、重连超时、轮次，只对这一次任务有效，不写回配置文件。

## 7. 怎么判

升级不设总时长上限。眼镜主控一轮实测大约 550～780 秒，包大小和机型一变就会变。只看还在不在动。

下面任一路在变，就继续等：

1. 页面百分比变了
2. 页面文案或界面变了
3. 固件数据还在传（眼镜看日志里的进度和写入偏移，只认上升）

三路都连续 300 秒没有变化，才判卡住，记升级失败。备注写明已经多久没有进展。

同版本循环（当前 S1）：页面显示完成，并且能重新连上，就是成功。版本号变不变只写进备注，不因为没变改判失败。

App 被切到后台时，不把「读不到页面」当成升级失败。只等它回来，每隔一会儿温和拉回前台，不按返回、不重启 App。

| 结果 | 含义 | 任务还跑不跑 |
| --- | --- | --- |
| PASS | 升级成功；需要重连时也重连成功 | 继续 |
| FAIL_UPGRADE | 升级或校验失败，设备还能连 | 可恢复则重试一次，然后继续 |
| HUNG_DEVICE | 断开后超过重连超时，连续确认仍未连接 | 停，后面记跳过 |
| SKIP | 这轮没测到（注入没生效，或前面已经死机） | 连续跳过过多才停 |
| ABORT_ENV | 手机掉线、蓝牙关、未登录、电量低、后台没包 | 立刻停 |
| STALE_POLICY | 后台策略和预期不符 | 停；single 模式下可暂停等人处理 |

死机确认：第一次看到未连接记下时间；120 秒内回来算正常重启；180 秒仍未连接，再连续 3 次探测都是未连接，才记死机。确认前会看手机还在、蓝牙开着、App 还在、没有飞行模式、屏幕没锁死。任一不满足，记环境异常，不算设备死机。

报告矩阵每格只留 PASS、FAIL、HUNG、SKIP。同一列里有死机记 HUNG，有升级失败记 FAIL，全部通过才记 PASS。重试后才通过的，报告「尝试」列会写成 `1.FAIL_UPGRADE → 2.PASS`，备注用黄底，表示这条不稳定。

报告目录：`output/reports/<链路_策略_时间戳>/`，里面有 `report.html`、`report.csv`、`result.json`。日志在 `output/` 对应任务目录。截图和界面 dump 在 `runtime/`，页面上可以清空，不清报告。

## 8. 程序怎么拆

```
网页 或  桌面窗口
        │
        ▼
本地接口（任务、设备、报告、自检）
        │
        ▼
调度器：一台手机、一条任务、用例串行
        │
        ├── 手表流程
        ├── 眼镜流程
        └── 戒指流程
        │
        ▼
手机驱动：adb、界面自动化、蓝牙探测、日志抓取
```

| 部分 | 位置 | 职责 |
| --- | --- | --- |
| 网页 | `web/` | 选任务、看进度、打开报告 |
| 桌面窗口 | `desktop/app.py` | 便携版用的同一套操作，直接调调度，不套浏览器 |
| 服务入口 | `start.py`、`server/app.py` | 源码开浏览器；exe 开窗口。只听本机 |
| 任务接口 | `server/api/tasks.py` | 创建、停止、继续、查状态、拉日志 |
| 调度 | `server/engine/scheduler.py` | 单任务锁、按轮次调用对应流程、写报告、看门狗 |
| 三条流程 | `server/scripts/run_*_flow.py` | 各 App 的点击、等待、读进度 |
| 公共步骤 | `server/links/` | 拉起、进升级页、点升级、读版本 |
| 判定 | `server/engine/judge.py`、`strategy.py` | 死机确认、一轮收口、S1/S2 版本检查 |
| 手机驱动 | `server/drivers/` | adb、uiautomator2、蓝牙状态、日志、假设备 |
| 配置 | `config/` | 全局参数、三条 App、九条用例 |
| 报告 | `server/common/report_builder.py` | HTML、CSV、JSON |

真机任务走三条 `run_*_flow.py`。`server/engine/state_machine.py` 只给 `--dry-run` 用。改 `upgrade_total_timeout` 不影响真机判定。

改完 `server/` 下的代码要停掉服务再启动。进程把模块加载在内存里，不重启，新任务仍跑旧逻辑。

## 9. 配置分工

| 文件 | 改什么 |
| --- | --- |
| `config/global.yaml` | 观察窗、重连超时、卡住秒数、用例间隔、重试次数、电量下限、S2 模式 |
| `config/app_watch.yaml` `app_glass.yaml` `app_ring.yaml` | 包名、按钮文案、成功/失败文案、进度来源 |
| `config/cases/*.yaml` | 每条用例的干扰动作和通过标准 |

App 改版后，按 `docs/元素校准.md` 对一下包名和页面文案。包名若仍是 `com.example.*`，真机任务会被拒绝。文案不变就不用改配置；定位优先跟稳定文案，不绑容易变的控件 id。

换手机时，若系统设置里的蓝牙、Wi-Fi 开关点不到，要在手机控制的兜底点击里补上该机型的控件。开跑前用页面上的「蓝牙/Wi-Fi自检」确认这台手机能被开关。

## 10. 数据放哪

源码运行时，数据在项目目录：

- `config/` 配置
- `output/` 报告和日志
- `runtime/` 临时文件，可清空

便携版数据在 exe 旁边的 `WearableOTA_data\`，已有配置不会被新 exe 覆盖。自带 adb。和本机其他 adb 抢手机时，先关掉别的工具。

# 操作手册

## 开跑前

1. 在 PHP 后台把升级包配好。本工具不会改后台。
2. 手机打开 USB 调试，只连一台，手机上点允许。`adb devices` 里应只有一台，状态是 `device`。
3. App 已安装，并且已经登录。登录不在用例里。
4. 穿戴设备已在 App 里连上。眼镜电量够再升（低于提示阈值会直接停）。

## 打开工具

测试人员：双击 `WearableOTA.exe`。

开发调试：在项目目录执行 `python start.py`，浏览器打开后用页面操作。

## 跑一轮

1. 选 App：眼镜、戒指或手表。
2. 点「刷新设备」，看手机型号、系统、App 版本、穿戴设备是否填上。不对就手改这一栏，只影响本份报告。
3. 点「蓝牙/Wi-Fi自检」。失败就先不要开任务。
4. 勾要用的场景，每条填次数。全量就点「全量运行」。T02 和 T03 不要一起勾。
5. 眼镜若要升影音，在固件模块里勾上。不勾就是主控。
6. 点「开始任务」。右侧看当前步骤、成功/失败计数和日志。
7. 跑完后，在「报告」里打开 HTML，或到 `output/reports/` 里取文件。

换下一台：点「停止」，拔线，插上下一台，点「刷新设备」，再新建任务。

## 结果怎么读

- 成功：升级完成，该连上也连上了。
- 失败：升级没成，或重新点升级后仍没成。看备注第一句。
- 死机：设备断开后一直没回来。后面的场景不会再跑。
- 跳过：这轮没测到，或因为前面死机被跳过。
- 环境异常：没包、没登录、电量低、手机不在。整场停止。去处理后重新开任务。
- 黄底备注：这一条是重试后才过的，不算一次干净通过。

任务停住并提示去后台换包时，换好后点「继续」。

## 不要做的事

- 升级过程中不要手动抢这台手机去连别的设备。工具会等，但容易把现场搞乱。
- 不要在已经开始写固件之后，让工具或人手立刻整包再刷一遍。
- 息屏用例失败，记成设备问题，不要改工具让它算通过。
